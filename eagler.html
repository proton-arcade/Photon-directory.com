Biggest thing in the folder

Minecraft 1.8, in one HTML file, on this machine.

Eaglercraft.html sits at the root of this hub: the client, the assets and the launcher, base64'd and gzipped into 17.2 MB of text. On launch it inflates itself with DecompressionStream, falls back to a worker on older browsers, then builds the game. This page does not do that work for it — it just decides when it happens.

Which is why the frame is empty until you ask. Loading it by default would put 17 MB in front of anyone who only came to read the index.

What the file actually does

StageWhat happens
ReadTwo giant base64 blobs are pulled out of <script> tags in its own head — one signed, one the client.
InflateGunzipped through DecompressionStream, or a worker if that is missing. This is the part that takes seconds.
Hand-offThe inflated code becomes a blob URL and is appended as a script tag. If the browser will not let the page XHR a blob, it falls back to a data: URL, which is slower.
BootA five second countdown, a skip button, then its own boot menu with showBootMenuOnLaunch left on.
PlayJava-flavoured 1.8.8 semantics on a canvas: chunks, redstone, the whole thing, running on a translated JVM core.

This build carries its own notice: “This file is from 07/06/2025”, with a link to the upstream site for anything newer. The hub keeps the file exactly as it arrived — one byte changed and the signature stage would complain.

Read before you blame the hub

Four things that will go wrong, and why

SymptomCause and what to do
It sits on “Decompressing…” for a long time Normal on a slow disk or a phone: 17 MB of base64 has to become about 30 MB of code. On a machine with no DecompressionStream it uses the worker path, which is slower again. Give it twenty seconds before you decide it hung.
The mouse will not turn the head Pointer lock needs a click inside the frame first, and some browsers refuse it inside an embedded frame at all. Use “Open in its own tab”, where it always works.
Multiplayer says it cannot connect Expected with no network. The file is wired to three public relays (relay.deev.is, relay.lax1dude.net, relay.shhnowisnottheti.me) and those are not in this folder. Singleplayer, including a locally created world, never touches them.
Worlds vanished They live in IndexedDB under the name worlds, which is tied to the origin you played from. Opened from file:// yesterday and over http://localhost today? Those are different origins and you have two separate sets of worlds. “Delete saved worlds” empties the one you are on now.

One more: this is a re-distribution of a Java game's client, in a browser, by way of EaglercraftX. The hub ships it unmodified and claims nothing about it. If you want to keep it, keep the file, because there is no download step anywhere on this page.
